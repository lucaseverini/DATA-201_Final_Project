## Database Architecture

### Operational Database (OLTP)

The operational database consists of these key tables:

1.⁠ ⁠*Teams* - Team information (⁠ TeamID ⁠, ⁠ TeamName ⁠, ⁠ ShortName ⁠, etc.)
2.⁠ ⁠*Seasons* - Season data (⁠ SeasonID ⁠, ⁠ SeasonName ⁠, ⁠ StartDate ⁠, ⁠ EndDate ⁠)
3.⁠ ⁠*Referees* - Referee information (⁠ RefereeID ⁠, ⁠ RefereeName ⁠, etc.)
4.⁠ ⁠*Divisions* - League divisions (⁠ DivisionID ⁠, ⁠ DivisionCode ⁠, ⁠ LeagueName ⁠)
5.⁠ ⁠*Matches* - Core match data (⁠ MatchID ⁠, ⁠ Date ⁠, ⁠ HomeTeamID ⁠, ⁠ AwayTeamID ⁠, scores, etc.)
6.⁠ ⁠*MatchStatistics* - Detailed match stats (shots, fouls, cards, etc.)
7.⁠ ⁠*Bookmakers* - Betting companies information
8.⁠ ⁠*Markets* - Types of betting markets
9.⁠ ⁠*BettingOdds* - Actual odds from bookmakers

### Analytical Database (OLAP)

The analytical database uses a star schema:

1.⁠ ⁠*dim_Time* - Time dimension table
2.⁠ ⁠*fact_MatchResult* - Match outcomes and scores
3.⁠ ⁠*fact_TeamMatchStats* - Team-level statistics per match
4.⁠ ⁠*fact_LeagueSnapshot* - Point-in-time standings for teams

### ETL Process

The current ETL workflow:
1.⁠ ⁠CSV files loaded into staging (⁠ stg_premier_league_raw ⁠)
2.⁠ ⁠Data transformed from staging to operational tables
3.⁠ ⁠Operational data transformed to analytical tables
4.⁠ ⁠League table snapshots generated on schedule
